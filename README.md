# Классный журнал — образовательная платформа

MVP образовательной платформы для небольших учебных групп (вдохновлено Google Classroom).
Структура: **Курс → Уроки → Домашние задания → Ответы учеников.** Учитель создаёт курс,
подключает к нему учеников — и они автоматически получают доступ ко всем урокам и заданиям
курса, без ручного дублирования для каждого ученика.

## Технологии

- **Backend:** Node.js + Express — чистый JSON API (без шаблонизатора)
- **Frontend:** обычные статические `.html` файлы + vanilla JS (`fetch`), без React/Vue/EJS
  и без сборки — открыл файл в браузере через сервер и всё работает
- **Хранилище данных:** JSON-файлы в папке `data/` — без внешней базы данных
- **Файлы:** загружаются на диск в `uploads/`, отдаются только авторизованным пользователям
  через защищённый роут `/files/:filename`
- **Аутентификация:** сессии (`express-session`) + хеширование паролей (`bcryptjs`)

## Установка и запуск

```bash
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`. Порт можно переопределить переменной окружения `PORT`.
При первом запуске автоматически создадутся пустые файлы данных в `data/` и папка `uploads/`.

## Как попробовать

1. Откройте `http://localhost:3000` → зарегистрируйтесь как **Учитель**.
2. В другом браузере (или окне инкогнито) зарегистрируйтесь как **Ученик**.
3. От имени учителя: «Курсы» → «Создать курс», заполните форму и отметьте ученика в списке
   подключаемых.
4. Откройте курс → «Добавить урок» → заполните и сохраните.
5. На странице урока → «Добавить задание» — домашнее задание сразу станет видно
   **всем** ученикам курса, без дополнительных действий.
6. От имени ученика: «Мои курсы» → откройте курс → откройте урок → сдайте домашнее задание
   (файл и/или комментарий).
7. От имени учителя: «Домашние работы» (или прямо на странице урока) → «Открыть» напротив
   сданной работы → оставьте комментарий — ученик сразу увидит его на странице урока.

## Архитектура

Frontend и backend разделены полностью: HTML-страницы не содержат чужих данных и отдаются
статикой, вся логика доступа и данные — только через JSON API (`/api/...`). Поэтому
защищать нужно не HTML (он у всех одинаковый), а сами API-запросы — это и происходит на
сервере в `middleware/auth.js` и внутри каждого роута.

```
server.js               точка входа: сессии, статика, монтирование API-роутов
db/                      слой хранения данных (JSON-файлы)
  store.js                универсальный движок чтения/записи коллекций
  users.js, courses.js, lessons.js, homeworks.js, submissions.js
middleware/
  auth.js                 проверка сессии и роли — отдаёт 401/403 в JSON
  upload.js                multer: лимит 50 МБ, белый список форматов по каждому полю
routes/
  auth.js                  /api/register, /api/login, /api/logout, /api/me
  teacher.js                /api/teacher/... (курсы, уроки, задания, работы, ученики)
  student.js                 /api/student/... (курсы, уроки, сдача заданий)
  files.js                    /files/:filename — защищённая отдача файлов
public/                  ВСЯ статика — то, что видит браузер
  index.html, login.html, register.html, 404.html
  teacher/*.html, student/*.html   — по одной странице на экран, без шаблонов
  css/style.css             дизайн-система
  js/
    api.js                   обёртка над fetch (JSON + куки сессии)
    utils.js                  форматирование дат/размеров, экранирование HTML
    app-shell.js               проверка сессии при загрузке страницы + рендер навигации
    ui.js                       модалки, форма удаления с подтверждением, редактор текста
    pages/*.js                   логика конкретной страницы (одна страница — один файл)
data/                    JSON "база данных" (создаётся автоматически)
uploads/                 загруженные файлы (создаётся автоматически)
```

### Модель данных

```
Course  { teacherId, title, description, coverImage, studentIds[] }
Lesson  { courseId, teacherId, title, content, coverImage, attachments[], video, deadline }
Homework{ lessonId, teacherId, title, description, deadline }
Submission{ homeworkId, lessonId, studentId, file, comment, status, teacherComment }
```

Доступ ученика к уроку всегда проверяется через `course.studentIds` — у самого урока
собственного списка учеников больше нет. Как только учитель добавляет ученика в курс,
тот сразу видит все существующие и будущие уроки и задания курса.

### Как в будущем подключить настоящую базу данных

Все обращения к данным идут только через модули в `db/` (`courses.js`, `lessons.js` и т.д.),
построенные поверх `db/store.js` (JSON-файлы). Чтобы перейти на PostgreSQL/MongoDB/что угодно,
достаточно переписать `store.js` (или сами модули `db/*.js`) — роуты и фронтенд трогать не
придётся, так как они работают с обычными JS-объектами, а не с форматом хранения напрямую.

## Реализованная базовая безопасность

- Обязательные поля проверяются на сервере (регистрация, курс, урок, задание, сдача работы)
- API учителя и API ученика разделены и защищены по роли (`requireRole` → 401/403)
- HTML-страницы сами по себе не содержат чужих данных, поэтому раздаются статикой; реальная
  защита — на уровне API-запросов, которые эти страницы делают
- Курс/уроки/файлы/задания доступны только владельцу-учителю или подключённым ученикам —
  включая прямые ссылки на файлы (`/files/:filename` всегда проверяет права через курс)
- Ограничение размера файла — 50 МБ, проверка формата по белому списку расширений (отдельно
  для обложки, видео и вложений)
- Удаление курса и урока требует ввода слова «УДАЛИТЬ» для подтверждения (и на клиенте, и
  повторно на сервере)
- Пароли хранятся только в виде bcrypt-хэша

Это минимальный набор, соответствующий ТЗ («без сложных механизмов»), не production-grade
защита (нет CSRF-токенов, rate limiting и т.п.) — для реального продакшена стоит добавить и их.

## Известные ограничения MVP

- Подключение ученика к курсу делает учитель вручную (чекбоксы в форме курса) — отдельного
  механизма приглашений/кодов нет.
- На один урок — одно домашнее задание.
- Сессии хранятся в памяти процесса — перезапуск сервера разлогинивает всех (данные в `data/`
  при этом не теряются, это разные вещи).
- Хранилище на JSON-файлах не рассчитано на высокую конкурентную нагрузку — для MVP и
  небольших групп этого достаточно (см. раздел выше про переход на БД).

## Тестирование

Полный сценарий (регистрация обеих ролей → курс с учеником → урок → домашнее задание →
автоматическая видимость у ученика → сдача работы → проверка учителем → комментарий →
удаление с подтверждением) прогнан через реальный headless-браузер и через прямые запросы
к API — включая проверки прав доступа к чужим курсам/файлам, лимит 50 МБ и белый список
форматов файлов.
